# Руководство пользователя «Управление маркетплейсами на 1С»

Генератор клиентской инструкции по модулю «Управление маркетплейсами на 1С». Текст ведётся в общем
Google Doc; скрипт сборки превращает его в веб-страницу с навигацией, поиском и фильтром по маркетплейсу,
а также в файл Word. Сайт пересобирается автоматически каждую ночь.

- Сайт: https://emple1.github.io/marketplace-guide/
- Источник текста: Google Doc (ссылка — `config.json` → `google_doc`)
- Матрица функционала: Google Таблица (`config.json` → `matrix_sheet`)

## Архитектура

```
Google Doc ──(export?format=docx)──┐
Google Sheet ──(export?format=csv)─┤
                                   ▼
                              build.py
             сжатие картинок → mammoth → постобработка → template.html
                                   │
          ┌────────────────────────┼─────────────────────────┐
          ▼                        ▼                         ▼
  dist/<имя>.html           dist/<имя>.docx             dist/web/
  один файл (~26 МБ),       документ Word               версия для сайта:
  Word встроен внутрь       без служебных таблиц        index.html, img/, instrukciya.docx,
                                                        stats.json, sections.json
                                                             │
                                          tools/check_and_prepare.py
                                (проверка объёма, changes.json → site/)
                                                             │
                                                             ▼
                                                      GitHub Pages
```

Версии отличаются способом хранения картинок:

- **Версия для сайта** — лёгкая страница (~1,2 МБ), скриншоты отдельными файлами, загружаются по мере прокрутки.
- **Однофайловая версия** — для отправки по почте или в мессенджере: `.docx` встроен в HTML в base64,
  картинки страница достаёт из него в браузере, поэтому они не хранятся дважды.

## Сборка вручную

```bash
pip install -r requirements.txt
python build.py                        # скачать Google Doc по ссылке из config.json
python build.py путь/к/файлу.docx      # собрать из локального .docx
python build.py --separate-docx        # не встраивать .docx в однофайловую версию
python build.py --no-compress          # не сжимать скриншоты
```

Просмотр версии для сайта (через `file://` не работают `fetch` и часть API, нужен локальный сервер):

```bash
python -m http.server 8766 --directory dist/web
```

Однофайловую версию достаточно открыть двойным щелчком.

Сборка печатает сводку и предупреждения: битые ссылки в документе, строки матрицы, не нашедшие раздела,
число подставленных ссылок на техподдержку.

## Конвейер сборки (`build.py`)

1. **Загрузка.** `download_google_doc` скачивает `…/export?format=docx`. Ответ с HTML вместо файла
   означает закрытый доступ — сборка останавливается с понятной ошибкой.
2. **Оптимизация картинок** (`optimize_docx`). PNG внутри `.docx` квантуются до палитры 256 цветов
   (`Image.quantize`, FASTOCTREE), стороны больше 2000 px уменьшаются. На скриншотах интерфейса разница
   не видна; объём документа падает примерно с 64 до 19 МБ. Разметка Word не меняется.
3. **Служебные данные.** `strip_matrix_from_docx` убирает из клиентского Word таблицу «Функционал по
   маркетплейсам» (если она есть в документе). `background_media` находит картинки, вставленные
   «за текстом» (`wp:anchor` с `behindDoc="1"`) — это фоновые подложки страниц, на сайте они не нужны.
   `media_index` строит соответствие «хэш содержимого → путь картинки внутри `.docx`».
4. **Конвертация.** mammoth переводит `.docx` в HTML. Для каждой картинки `convert_image` проставляет
   `width`/`height` (чтобы страница не прыгала при загрузке; высокие схемы ограничиваются 900 px по
   высоте, `MAX_SHOW_HEIGHT`) и вместо данных пишет ссылку на файл внутри `.docx` (`data-media`).
5. **Постобработка** (`postprocess`, BeautifulSoup):
   - удаляются титульный лист, пустые абзацы, ручное «Содержание» и фоновые подложки;
   - заголовки получают `id` из текста (кириллицей, без повторов) и значок «скопировать ссылку»;
   - внутренние ссылки Google Docs (`#heading=h.…`, `#_heading=…`) и ссылки на этот же документ
     переводятся на новые якоря; если закладка потеряна, раздел ищется по тексту ссылки
     (точное совпадение заголовка → начало заголовка → жирный абзац); не найден — ссылка становится
     текстом и попадает в предупреждения;
   - абзац из картинок становится `<figure>`, следующий абзац «Рисунок N …» — подписью;
   - абзацы, начинающиеся с «Важно:», «Совет:», «Осторожно:», «Примечание:» и синонимов, становятся
     цветными выносками (`CALLOUTS`);
   - таблицы оборачиваются в контейнер с горизонтальной прокруткой, внешние ссылки открываются в новой вкладке;
   - удаляются списки-перечисления маркетплейсов (их заменяют оглавление и фильтр);
   - фразы «обратитесь в поддержку» и подобные становятся ссылкой на `support_url` (`link_support`);
   - разделы размечаются по маркетплейсам для фильтра (`tag_marketplaces`, см. ниже).
6. **Запись результатов.**
   - Однофайловая версия: `.docx` в `<script type="application/octet-stream">` (base64).
   - Версия для сайта: картинки извлекаются в `img/` (PNG пересохраняется в WebP без потерь, если так
     меньше — `web_image`), в разметке `data-media` заменяется на `data-src`.
   - `stats.json` — число заголовков и картинок (для защиты от случайного удаления).
   - `sections.json` — отпечатки разделов (для «Что нового»).

## Возможности страницы и их реализация

### Оглавление
Строится в браузере из `h1–h3[id]`. Дерево: у пунктов с подразделами есть стрелка; по умолчанию открыты
верхний уровень и ветка текущего раздела, «Развернуть»/«Свернуть» переключают режим (`toc-mode` в
`localStorage`). Текущий раздел определяется обработчиком `scroll` (с ограничением частоты и финальным
вызовом), а не `IntersectionObserver`: так подсветка не зависает, когда вкладка в фоне.

### Поиск
Два уровня:
1. **Разделы** — функция `smart`. Запрос разбивается на слова, отбрасываются стоп-слова, каждое слово
   расширяется синонимами (`SYN`: «вб» = WB = РВБ = Wildberries, «чз» = маркировка, «ключ» = токен и т. д.).
   Формы слов сопоставляются по основе (`stem` — усечение окончания, «установить» находит «Установка»).
   Совпадение в заголовке весит 10, в заголовках выше — 4, в тексте — 1; раздел должен содержать все
   слова запроса. Если в запросе есть маркетплейс, разделы других маркетплейсов отбрасываются.
   Выводятся 8 лучших, Enter открывает первый, ↑/↓ — выбор.
2. **Точные совпадения** — фраза подсвечивается `<mark>` в тексте, стрелки переходят между совпадениями.

Поле поиска закреплено вверху боковой панели. Поиск учитывает текущий фильтр по маркетплейсу.

### Фильтр по маркетплейсу
При сборке каждый элемент содержимого получает `data-mp="wb ozon …"`: маркетплейс назван в заголовке
раздела (регулярные выражения `MARKETPLACES`) → по матрице функционала → наследуется от заголовка выше →
иначе раздел общий. Родительский заголовок получает и маркетплейсы своих подразделов. `data-mp-own` —
маркетплейс назван в самом заголовке; по нему решается, показывать ли кнопку маркетплейса.

В браузере выбор добавляет класс `mp-hidden` лишним элементам и пунктам оглавления, показывает плашку
«Показаны разделы только по …», сохраняется в `localStorage` и в адресе (`?mp=wb`), так что ссылку с
фильтром можно отправить клиенту. Коды: `wb`, `ozon`, `ym`, `mm`, `ali`, `mvideo`, `lamoda`, `magnit`.

### «Что нового»
Разделы, добавленные или изменённые за последние 14 дней.
- `build.py` → `section_index` пишет `sections.json`: для каждого h1–h3 — `id`, заголовок и хэш
  собственного текста раздела (до следующего заголовка) вместе с хэшами содержимого его картинок.
  Разметка фильтра и перенумерация картинок на хэш не влияют, замена скриншота — влияет.
- `check_and_prepare.py` скачивает с сайта предыдущие `sections.json` и `changes.json`, помечает новые
  `id` как «новый», изменившийся хэш — как «обновлён», отбрасывает записи старше 14 дней и кладёт
  `changes.json` в `site/`. Первая публикация служит точкой отсчёта; если изменилось больше 40 % разделов,
  это считается перестройкой документа и в список не попадает.
- Страница загружает `changes.json` через `fetch` и показывает до 10 записей в сворачиваемом `<details>`,
  пропуская разделы, скрытые фильтром. В однофайловой версии блока нет.

### Изображения
- **Ленивая загрузка (сайт):** `IntersectionObserver` с `rootMargin: 2500px` подставляет `src` из
  `data-src` примерно за три экрана до картинки; пока она грузится, видна анимированная заглушка.
  Перед печатью загружаются все картинки (`beforeprint`).
- **Однофайловая версия:** скрипт разбирает zip-структуру встроенного `.docx` (центральный каталог),
  распаковывает картинки через `DecompressionStream('deflate-raw')` и подставляет `blob:`-ссылки.
  Для браузеров без этого API показывается предупреждение.
- **Увеличение:** щелчок по картинке открывает её в полноэкранном лайтбоксе, Esc или щелчок закрывают.

### Скачать Word
На сайте — обычная ссылка на `instrukciya.docx`. В однофайловой версии кнопка собирает `Blob` из
встроенного base64 и скачивает его через временную `blob:`-ссылку.

### Тема
Цвета заданы CSS-переменными на `:root`; тёмная палитра включается по `prefers-color-scheme` или
вручную кнопкой (`data-theme` на `<html>`, выбор хранится в `localStorage`). Белый фон вокруг логотипа
при сборке заменяется прозрачным (`transparent_corners`: заливка от углов с допуском), поэтому в тёмной
теме логотип не стоит на белом квадрате. Исходный файл логотипа не меняется.

### Прочее
- **Ссылка на раздел:** значок у заголовка копирует адрес с якорем (Clipboard API) и показывает уведомление.
- **Шапка:** логотип ведёт на `home_url`, название — в начало страницы, ☰ скрывает боковую панель
  (на телефоне — открывает её поверх содержимого).
- **Кнопка «в конец»:** мгновенная прокрутка вниз (без плавной анимации, чтобы по пути не запускалась
  загрузка всех скриншотов); скрывается у конца страницы.
- **Сворачиваемые разделы:** заголовки из `collapsed` показывают только первый абзац и кнопку «Показать полностью».
- **Печать / PDF:** отдельные стили `@media print` скрывают интерфейс и выводят только содержимое.
- **Адаптивность:** при ширине до 980 px боковая панель превращается в выезжающее меню.
- **Состояние читателя** (`localStorage`, с обработкой ошибок доступа): тема, фильтр, режим оглавления,
  скрытая панель, свёрнутые разделы, открыт ли блок «Что нового».

## Публикация (GitHub Actions → Pages)

Workflow `.github/workflows/publish.yml`:

- **Запуск:** по расписанию `cron: "0 0 * * *"` (03:00 МСК; GitHub обычно запускает с задержкой) и
  вручную — Actions → «Публикация инструкции» → Run workflow.
- **Шаги:** установка зависимостей → `python build.py` → `tools/check_and_prepare.py` →
  `upload-pages-artifact` → `deploy-pages`.
- **Защита от случайного удаления:** `check_and_prepare.py` сравнивает `stats.json` сборки с
  опубликованным. Если заголовков или картинок стало меньше на 30 % и более, публикация прерывается,
  на сайте остаётся прошлая версия, GitHub присылает письмо об ошибке. Намеренное сокращение
  публикуется ручным запуском с флажком `force`.
- **Поддержание расписания:** последний шаг вызывает `gh api …/workflows/publish.yml/enable`, чтобы GitHub
  не отключил cron после 60 дней без коммитов.

Правки в Google Doc и Google Таблице попадают на сайт при ближайшей публикации. Правки кода и
`config.json` — после `git push` и ближайшей публикации. После обновления сайта браузер может показывать
старую копию — помогает Ctrl+F5.

## Правила для авторов документа

1. **Структура — стилями «Заголовок 1/2/3».** Из них строятся оглавление, якоря и поиск по разделам.
   Жирный обычный текст заголовком не считается.
2. **Название маркетплейса — в заголовке** раздела про один маркетплейс: «Ozon - …»,
   «РВБ (Wildberries) - …». На этом работает фильтр.
3. **Скриншоты** — картинкой «в тексте» (не «перед текстом»/«за текстом»), отдельным абзацем.
   Подпись — следующим абзацем: «Рисунок N – …».
4. **Выноски** — абзац начинается со слова с двоеточием:
   `Важно:` / `Внимание:` / `Обратите внимание:` — жёлтая; `Осторожно:` / `Нельзя:` — красная;
   `Совет:` / `Подсказка:` — зелёная; `Примечание:` / `Заметка:` — синяя.
5. **Ссылки на другие разделы** — «Вставить ссылку → Заголовки в документе», а не копированием адреса.
6. **Доступ к документу** «Все, у кого есть ссылка — читатель» не закрывать: иначе сайт перестанет обновляться.
7. **Новый общий раздел** (без маркетплейса в названии) — добавить строку в матрицу функционала.

## Матрица функционала

Определяет, к каким маркетплейсам относятся общие разделы («Управление ценами», отчёты, маркировка…).

- **Источник:** Google Таблица из `matrix_sheet` (доступ «по ссылке — читатель»), скачивается как CSV
  (`load_matrix_sheet`). Если недоступна — `matrix.csv` в проекте (UTF-8, разделитель `;`). Если в самом
  Google Doc есть таблица «Функционал по маркетплейсам», её строки дополняют матрицу, а сама таблица
  убирается со страницы и из Word.
- **Формат:** первая строка — «Раздел | WB | Ozon | Яндекс Маркет | …» (столбцы распознаются по названию
  маркетплейса); далее — названия разделов как в документе (допускается начало названия; «— » перед
  подразделом игнорируется). В ячейке `+` — есть, пусто — нет, `?` — не уверены (считается «есть»).
- **Правила:** раздел без отметки у маркетплейса скрывается при его фильтре; раздела нет в матрице —
  виден при любом фильтре; подразделы наследуют отметки раздела.

## Диагностика

| Симптом | Причина и решение |
|---|---|
| Публикация упала на шаге сборки | Закрыт доступ к Google Doc по ссылке — открыть «читатель по ссылке» |
| «СТОП: разделов стало …» | Из документа удалена большая часть текста. Если намеренно — Run workflow с `force` |
| «строка матрицы не нашла раздел» | Опечатка в названии раздела в матрице или раздел переименован |
| «битая ссылка в документе» | Ссылка ведёт на удалённый заголовок — перепривязать в Google Doc |
| На сайте старая версия | Кэш браузера — Ctrl+F5; проверить, что последний запуск в Actions зелёный |
| Картинки не появляются в однофайловой версии | Устаревший браузер без `DecompressionStream` — открыть в актуальном Chrome / Edge / Firefox |
