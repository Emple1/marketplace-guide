# Инструкция по модулю маркетплейсов

Клиентская инструкция собирается из **общего Google Doc** в один HTML-файл:
оглавление, поиск, увеличение скриншотов, тёмная тема, печать в PDF и кнопка **«Скачать Word»**
(сам .docx встроен внутрь HTML, поэтому клиенту отправляется один файл).

## Как дополнять (для всех)

Пишем **только в Google Doc** — ссылка в `config.json`, поле `google_doc`.

1. **Структура — через стили заголовков.** «Заголовок 1» — большой раздел, «Заголовок 2» — подраздел,
   «Заголовок 3» — пункт. Из них строится оглавление. Жирный обычный текст в оглавление не попадает.
2. **Скриншоты** — вставлять картинкой «в тексте» (не «перед текстом/за текстом»), отдельным абзацем.
   Подпись — следующим абзацем, начиная с «Рис. …» (или целиком курсивом).
3. **Выноски** — абзац, начинающийся со слова с двоеточием, станет цветной плашкой:
   - `Важно:` / `Внимание:` / `Обратите внимание:` — жёлтая;
   - `Осторожно:` / `Нельзя:` — красная;
   - `Совет:` / `Подсказка:` — зелёная;
   - `Примечание:` / `Заметка:` — синяя.
4. **Таблицы** — обычные таблицы Google Docs; первая строка оформляется как шапка.
5. **Фильтр по маркетплейсу.** Под названием инструкции есть кнопки «Wildberries / Ozon / Яндекс Маркет …»:
   при выборе остаются только разделы этого маркетплейса и общие разделы. Раздел относится к маркетплейсу,
   если тот **назван в заголовке** раздела или в заголовке выше: «Wildberries - Настройка профиля»,
   «OZON FBO формирование поставки», «РВБ (Wildberries) - …». Поэтому в заголовках разделов про один
   маркетплейс обязательно пишем его название. Ссылку с фильтром можно отправить клиенту:
   `…/?mp=wb` (коды: wb, ozon, ym, mm, ali, mvideo, lamoda, magnit).
   **Общие разделы** (без маркетплейса в названии: «Управление ценами», отчёты, маркировка…) скрываются по
   **матрице функционала** — файлу `matrix.csv` в проекте (`;`-разделитель, UTF-8): первая строка
   «Раздел;WB;Ozon;…», дальше — названия разделов как заголовки в документе (подраздел можно начать с «— »),
   `+` — есть, пусто — нет, `?` — не уверены (считается «есть»). Раздел без отметки у маркетплейса скрывается
   при его фильтре; раздела нет в матрице — виден при любом фильтре; подразделы наследуют отметки раздела.
   Матрицу ведёт Claude по чек-листу ответственного: **появился новый общий раздел — написать Claude
   одну строку** («раздел X — WB, Ozon»). Сборка печатает, сколько строк прочитано и какие не нашли раздел.
   (Запасной вариант: таблица «Функционал по маркетплейсам» в самом Google Doc — сборка тоже её прочтёт
   и уберёт со страницы и из Word.)
6. **История изменений** — в конце документа раздел «История изменений» с таблицей
   *Дата · Автор · Что изменено*. Каждое заметное изменение — новая строка.
7. Не удалять чужие разделы молча — оставить комментарий в Google Doc.

## Как выпустить новую версию (ответственный)

```bash
pip install -r requirements.txt   # один раз
python build.py
```

- Скрипт скачивает Google Doc (нужен доступ «Все, у кого есть ссылка — читатель»).
  Если доступ закрыт: «Файл → Скачать → Microsoft Word (.docx)» и `python build.py путь/к/файлу.docx`.
- Результат — в `dist/`:
  - `<название>.html` — **один файл** для отправки вручную (Word и скриншоты встроены, ~26 МБ, открывается дольше);
  - `<название>.docx` — тот же документ в Word;
  - `web/` — **версия для сайта**: лёгкая страница (~1 МБ) + папка `img/` со скриншотами, которые
    грузятся по мере прокрутки, + `instrukciya.docx` для кнопки «Скачать Word». Именно она публикуется на GitHub Pages.
- Перед отправкой поднять `version` в `config.json`, открыть HTML и пролистать.
- Закоммитить: `git commit -am "Версия 1.1"`. Сборка (`dist/`) в git не хранится — она весит десятки МБ;
  при необходимости любую версию можно пересобрать.
- Файл ~26 МБ — больше лимита вложений почты, клиентам удобнее давать ссылкой (Яндекс Диск / Google Drive).
- Скриншоты при сборке сжимаются (палитра 256 цветов, на глаз без разницы): 64 МБ → 19 МБ.
  Картинки на странице берутся из встроенного .docx, поэтому не хранятся дважды.
- Если .docx всё равно больше 40 МБ, он автоматически кладётся рядом с HTML
  (или принудительно: `--separate-docx`) — тогда клиенту отправлять оба файла.

## Автоматическая публикация (GitHub Pages)

Каждую ночь в 03:00 МСК GitHub сам скачивает Google Doc, собирает инструкцию и выкладывает её
по постоянному адресу `https://<аккаунт>.github.io/<репозиторий>/`. Клиентам даём эту ссылку один раз.
Настройка — `.github/workflows/publish.yml`.

- **Срочно опубликовать:** вкладка *Actions* → «Публикация инструкции» → *Run workflow*.
- **Защита:** если разделов или картинок стало на 30 % меньше, чем на сайте сейчас, публикация
  останавливается (на сайте остаётся прошлая версия), а GitHub присылает письмо об ошибке.
  Если удаление намеренное — *Run workflow* с галочкой *force*.
- **Если упало:** письмо от GitHub → открыть запуск → посмотреть, на каком шаге красный крестик.
  Чаще всего — у Google Doc закрыли доступ по ссылке.
- Изменения в оформлении (`template.html`, `config.json`) попадают на сайт после `git push`
  и ближайшей ночной сборки (или *Run workflow*).

## Настройки (`config.json`)

| Поле | Что это |
|---|---|
| `google_doc` | Ссылка на Google Doc или его ID |
| `title`, `kicker` | Заголовок и надпись над ним |
| `version` | Номер версии (на странице не показывается) |
| `file_name` | Имя файлов в `dist/` |
| `accent` | Фирменный цвет (`#2563eb`) |
| `logo` | Путь к логотипу (png/svg) в этой папке; пусто — буква в квадрате |
| `footer` | Строка внизу страницы |
| `collapsed` | Разделы, которые показываются свёрнутыми (виден первый абзац и кнопка «Показать полностью»), например `["Введение"]` |
| `home_url` | Куда ведёт логотип в шапке |
| `support_url` | Ссылка на техподдержку (подставляется в текст «обратитесь в поддержку» и в подвал) |

## Файлы

- `build.py` — сборка (mammoth: .docx → HTML, затем оформление и встраивание .docx).
- `template.html` — внешний вид страницы. Менять оформление — здесь.
- `tools/check_and_prepare.py` — проверка сборки перед публикацией.
- `.github/workflows/publish.yml` — ночная публикация.
