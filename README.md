# Инструкция по модулю маркетплейсов

Клиентская инструкция собирается из **общего Google Doc** в один HTML-файл:
оглавление, поиск, увеличение скриншотов, тёмная тема, печать в PDF и кнопка **«Скачать Word»**
(сам .docx встроен внутрь HTML, поэтому клиенту отправляется один файл).

## Как дополнять (для всех)

Пишем **только в Google Doc** — ссылка в `config.json`, поле `google_doc`.

1. **Структура — через стили заголовков.** «Заголовок 1» — большой раздел, «Заголовок 2» — подраздел,
   «Заголовок 3» — пункт. Из них строится оглавление. Жирный обычный текст в оглавление не попадает.
2. **Скриншоты** — вставлять картинкой «в тексте» (не «перед текстом/за текстом»), отдельным абзацем.
   Подпись — следующим абзацем, начиная с «Рис. …» (или целиком курсивом).
3. **Выноски** — абзац, начинающийся со слова с двоеточием, станет цветной плашкой:
   - `Важно:` / `Внимание:` / `Обратите внимание:` — жёлтая;
   - `Осторожно:` / `Нельзя:` — красная;
   - `Совет:` / `Подсказка:` — зелёная;
   - `Примечание:` / `Заметка:` — синяя.
4. **Таблицы** — обычные таблицы Google Docs; первая строка оформляется как шапка.
5. **История изменений** — в конце документа раздел «История изменений» с таблицей
   *Дата · Автор · Что изменено*. Каждое заметное изменение — новая строка.
6. Не удалять чужие разделы молча — оставить комментарий в Google Doc.

## Как выпустить новую версию (ответственный)

```bash
pip install -r requirements.txt   # один раз
python build.py
```

- Скрипт скачивает Google Doc (нужен доступ «Все, у кого есть ссылка — читатель»).
  Если доступ закрыт: «Файл → Скачать → Microsoft Word (.docx)» и `python build.py путь/к/файлу.docx`.
- Результат — в `dist/`: `Инструкция по модулю маркетплейсов.html` (+ тот же `.docx` отдельно).
- Перед отправкой поднять `version` в `config.json`, открыть HTML и пролистать.
- Закоммитить: `git commit -am "Версия 1.1"`. Сборка (`dist/`) в git не хранится — она весит десятки МБ;
  при необходимости любую версию можно пересобрать.
- Файл ~26 МБ — больше лимита вложений почты, клиентам удобнее давать ссылкой (Яндекс Диск / Google Drive).
- Скриншоты при сборке сжимаются (палитра 256 цветов, на глаз без разницы): 64 МБ → 19 МБ.
  Картинки на странице берутся из встроенного .docx, поэтому не хранятся дважды.
- Если .docx всё равно больше 40 МБ, он автоматически кладётся рядом с HTML
  (или принудительно: `--separate-docx`) — тогда клиенту отправлять оба файла.

## Настройки (`config.json`)

| Поле | Что это |
|---|---|
| `google_doc` | Ссылка на Google Doc или его ID |
| `title`, `kicker` | Заголовок и надпись над ним |
| `version` | Версия, показывается в шапке |
| `file_name` | Имя файлов в `dist/` |
| `accent` | Фирменный цвет (`#2563eb`) |
| `logo` | Путь к логотипу (png/svg) в этой папке; пусто — буква в квадрате |
| `footer` | Строка внизу страницы |

## Файлы

- `build.py` — сборка (mammoth: .docx → HTML, затем оформление и встраивание .docx).
- `template.html` — внешний вид страницы. Менять оформление — здесь.
