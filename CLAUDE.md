# Инструкция по модулю «Управление маркетплейсами на 1С» — описание проекта

Этот файл описывает проект целиком: что это, как устроено, какие решения уже приняты и почему.
Если история чата с Claude потерялась, пришлите ему этот файл (или откройте Claude Code в этой папке —
он прочитает `CLAUDE.md` сам) и продолжайте с того места, где остановились.

Последнее обновление описания: 16.10.2026.

---

## 1. Что это и зачем

Клиентская инструкция (руководство пользователя) по модулю **«Управление маркетплейсами на 1С»**
компании **Инфософт** (Wildberries, Ozon, Яндекс Маркет, МегаМаркет, AliExpress, М.Видео, Lamoda;
конфигурации УТ 11.5 / КА / ERP / УНФ / Розница).

- **Источник правды — общий Google Doc**, который пополняют коллеги:
  https://docs.google.com/document/d/11anaRyEBq1x_Q3e3W04CKyGhtZZDfacE/edit
  (доступ «Все, у кого есть ссылка — читатель» обязателен, иначе автосборка не скачает документ).
- Из него автоматически собирается **красивая HTML-страница** с кнопкой **«Скачать Word»**.
- **Сайт для клиентов:** https://emple1.github.io/marketplace-guide/ (GitHub Pages).
- **Репозиторий:** https://github.com/Emple1/marketplace-guide (публичный — на бесплатном тарифе
  Pages работает только с публичными), ветка `main`.
- **Папка на компьютере:** `D:\Инструкция маркетплейсы\` (отдельно от хранилища Obsidian `D:\Obsidian sink`).
- Задачу поставила начальница; инструкцию постоянно дополняют коллеги.

## 2. Как это работает (схема)

```
Google Doc ──(экспорт .docx по ссылке)──► build.py
                                             │ 1. сжимает скриншоты внутри .docx (64 МБ → ~19 МБ)
                                             │ 2. mammoth: .docx → HTML-фрагмент
                                             │ 3. постобработка (BeautifulSoup) — см. раздел 5
                                             │ 4. вставляет в template.html
                                             ▼
             dist/<название>.html  — ОДИН ФАЙЛ (~26 МБ): Word встроен, картинки берутся из него
             dist/<название>.docx  — тот же документ в Word
             dist/web/             — ВЕРСИЯ ДЛЯ САЙТА: index.html (~1 МБ) + img/ (скриншоты)
                                     + instrukciya.docx + stats.json
                                             │
GitHub Actions (каждую ночь 03:00 МСК) ──────┘──► tools/check_and_prepare.py ──► GitHub Pages
```

## 4. Команды

```bash
cd "D:\Инструкция маркетплейсы"
pip install -r requirements.txt          # один раз
python build.py                          # скачать Google Doc и собрать всё в dist/
python build.py "путь\к\файлу.docx"      # собрать из вручную скачанного .docx
python build.py --separate-docx          # однофайловая версия без встроенного Word
python build.py --no-compress            # не сжимать скриншоты
```

Посмотреть результат локально: двойной клик по `dist\<название>.html`, либо для версии сайта
`python -m http.server 8766 --directory dist/web` и открыть http://127.0.0.1:8766/.

Сборка печатает предупреждения: битые ссылки в документе, сколько убрано списков маркетплейсов,
сколько ссылок на техподдержку подставлено.

## 5. Что делает постобработка (`build.py → postprocess`)

По порядку:
1. Убирает титул/подзаголовок документа и **титульный лист** (всё до первого заголовка) — название в шапке.
2. Убирает пустые абзацы.
3. Убирает ручное **«Содержание»** из документа (h1 «Содержание»/«Оглавление» до следующего h1) — есть боковое оглавление.
4. **Заголовок, состоящий только из ссылок** (ошибка оформления в FAQ) → обычные абзацы-ссылки, по одной на строку.
5. Заголовкам даёт якоря (`id` из текста, кириллицей) + значок-скрепку «скопировать ссылку на раздел».
6. **Внутренние ссылки** Google Docs (`#_heading=h.xxx`) переводит на новые якоря. Закладка пустого заголовка
   переносится на следующий заголовок.
7. **Ссылки на этот же Google Doc** (`…/document/d/<id>/…#heading=h.xxx`) → внутренние ссылки на раздел
   (чтобы клиенты не уходили в исходник). Ссылка на документ целиком удаляется вместе с пунктом.
8. Если закладка потерялась — ищет раздел **по названию**: сначала ближайший заголовок ниже с тем же
   названием, потом начинающийся с него («Wildberries» → «Wildberries - Настройка профиля»), потом
   жирный абзац с тем же текстом. Не нашлось — ссылка становится текстом + предупреждение в выводе.
9. Абзац из картинок → `<figure>`; следующий абзац «Рисунок N …» / «Рис.» / целиком курсив → подпись.
10. Абзацы «Важно:/Внимание:/Обратите внимание:» (жёлтые), «Осторожно:/Нельзя:» (красные),
    «Совет:/Подсказка:» (зелёные), «Примечание:/Заметка:» (синие) → цветные выноски.
11. Таблицы — в обёртку с горизонтальной прокруткой. Внешние ссылки — в новой вкладке.
12. **Удаляет списки-перечисления маркетплейсов** (3+ строки подряд, где только «Wildberries», «OZON» …) —
    по просьбе пользователя; их заменяют оглавление и фильтр.
13. **Ссылки на техподдержку**: «обратитесь в (нашу) службу поддержки / техническую поддержку / поддержку»,
    «заявки на техподдержку» → ссылкой делаются слова про поддержку (`support_url`). Фразу про поддержку
    Lamoda не трогает.
14. Разделы из `collapsed` помечает `data-fold` (сейчас список пуст).
15. **Разметка по маркетплейсам** (`data-mp="wb ozon …"`) — для фильтра: раздел относится к маркетплейсу,
    если тот назван в его заголовке; иначе — по **матрице функционала**; иначе наследует от заголовка выше;
    иначе общий (виден всем). Заголовок получает ещё и маркетплейсы своих подразделов (чтобы подраздел
    не «повис» без родителя). `data-mp-own` — маркетплейс назван в самом заголовке: по нему строятся
    кнопки фильтра. Коды: `wb, ozon, ym, mm, ali, mvideo, lamoda, magnit`; `none` — ни одной галочки.

**Матрица функционала** — основной источник: **Google Таблица** (`config.json` → `matrix_sheet`;
`load_matrix_sheet` скачивает `…/export?format=csv` — первый лист, или `&gid=…`, если он есть в ссылке).
Таблица: https://docs.google.com/spreadsheets/d/1SHhIj1QCvhX0kYCxw2Q2WWchI0J917sMr8hqdl9rm2Q/edit
Её заполняют коллеги (решение пользователя: «сделаем Google Таблицу, при новом разделе ставят +»).
Не скачалась — предупреждение и запасной файл **`matrix.csv`** в корне проекта (UTF-8 с BOM, разделитель `;`; шапка
«Раздел;WB;Ozon;Яндекс Маркет;МегаМаркет;AliExpress;М.Видео;Lamoda;Магнит Маркет»). Строки — названия
разделов (точно или начало названия целыми словами; «— » перед подразделом игнорируется), столбцы
распознаются через `MARKETPLACES`, `+ ✓ да x ?` — есть (`?` = не уверены). Функции: `parse_matrix`,
`load_matrix_file`, `read_feature_matrix` (файл + запасной вариант — таблица «Функционал по маркетплейсам»
в Google Doc, её сборка убирает со страницы и из Word через `strip_matrix_from_docx`). Вывод сборки:
«матрица функционала (matrix.csv): N строк», «строка матрицы не нашла раздел: …».
Стартовый файл таблицы с черновиком Claude (55 строк, 16.10.2026, оформлен: подсказки «+»/«?», лист
«Как заполнять»): `Матрица функционала.xlsx` (в .gitignore) — пользователь загружает его в Google Диск,
открывает как Google Таблицу, даёт доступ и присылает ссылку → Claude вписывает её в `matrix_sheet`.

Сжатие картинок (`optimize_docx`): PNG → палитра 256 цветов (на скриншотах 1С разницы не видно, проверено
сравнением), стороны > 2000 px уменьшаются. Размеры на странице Word не меняются.

## 7. Возможности страницы (`template.html`)

- **Шапка:** ☰ (на компьютере скрывает/показывает боковую панель, на телефоне открывает меню),
  **логотип → сайт** (`home_url`, новая вкладка), **название → в начало страницы**, тема светлая/тёмная,
  «PDF» (печать), **«Скачать Word»**.
- **Фильтр по маркетплейсу** — кнопки под названием (Все / Wildberries / Ozon / Яндекс Маркет / МегаМаркет /
  AliExpress / М.Видео / Lamoda; кнопка показывается, только если у маркетплейса есть разделы с его именем
  в заголовке). Общие разделы скрываются по матрице функционала (см. раздел 5).
  Скрывает разделы других маркетплейсов, сокращает оглавление, поиск ищет только по видимому. Есть
  плашка «Показаны разделы только по …» с кнопкой «Показать все». Фильтр попадает в адрес: `?mp=wb` —
  такую ссылку можно дать клиенту.
- **Умный поиск** (закреплён вверху боковой панели): список подходящих **разделов** с учётом синонимов
  (вб = WB = РВБ = Wildberries, ям = Яндекс Маркет, озон, ламода, чз = маркировка, ключ = токен, цены,
  остатки, заказы, отчёты, обновление) и форм слов («установить» находит «Установка»). Если в запросе
  есть маркетплейс, разделы других маркетплейсов не показываются. Enter — первый результат,
  ↑↓ — выбор. Ниже — «точных совпадений в тексте: N» со стрелками перехода.
- **Оглавление-дерево:** по умолчанию основные разделы + раскрыта ветка текущего; стрелки ▸ у пунктов;
  кнопки «Развернуть»/«Свернуть». Текущий раздел подсвечивается при прокрутке.
- Скрепка у заголовков (при наведении) — копирует ссылку на раздел.
- Клик по скриншоту — увеличение. Круглая кнопка ↓ внизу справа — в конец инструкции (наверх — клик по названию в шапке; по просьбе пользователя). Мобильная вёрстка. Печать — без лишних элементов.
- **Версия для сайта:** скриншоты отдельными файлами, подгружаются заранее (за ~3 экрана, `data-src` +
  IntersectionObserver), пока грузятся — серая «переливающаяся» заглушка.
- **Однофайловая версия:** `.docx` встроен base64, картинки страница распаковывает из него в браузере
  (`DecompressionStream`), чтобы они не хранились дважды. Открывается медленнее (26 МБ).
- Браузер запоминает (localStorage): тему, фильтр, режим оглавления, скрытую панель, свёрнутые разделы.

## 8. Публикация (GitHub Actions → Pages)

- `publish.yml`: по расписанию `cron: "0 0 * * *"` (03:00 МСК) и вручную
  (Actions → «Публикация инструкции» → **Run workflow** → зелёная **Run workflow**; галочка *force* —
  публиковать несмотря на проверку).
- Шаги: `pip install` → `python build.py` (скачивает Google Doc) → `check_and_prepare.py` → деплой Pages →
  шаг «не дать GitHub отключить расписание» (`gh api … /enable`, против отключения через 60 дней без коммитов).
- **Защита:** если разделов или картинок стало на **30 %** меньше, чем в опубликованном `stats.json`,
  публикация останавливается (на сайте остаётся прошлая версия), GitHub присылает письмо.
- Изменения в коде (`template.html`, `build.py`, `config.json`) попадают на сайт после `git push` +
  ближайшей публикации. Изменения в Google Doc — просто после ближайшей публикации.
- На компьютере **нет `gh`**, поэтому запускать публикацию из Claude Code нельзя — только кнопкой на GitHub.
  Пуш работает через обычный `git push` (учётка Emple1 уже настроена).

## 9. Решения и пожелания пользователя (не откатывать)

- Плашки «Версия 1.0» и «Обновлено …» **убраны** с титула.
- Логотип Инфософт вместо буквы; **логотип → сайт**, **название → наверх** страницы.
- Списки ссылок «Wildberries / OZON / ЯндексМаркет …» **удалены совсем** (не превращены во внутренние).
- Вместо «#» у заголовков — значок-скрепка, видна только при наведении.
- Все ссылки в списке вопросов FAQ — одного вида (обычные ссылки).
- «Введение» **не сворачивать** (было сделано по недоразумению и откатено; просили сворачивать **оглавление**).
- Поиск не должен уезжать при переходе по совпадениям (закреплён).
- Для сайта — лёгкая версия; однофайловая — только для отправки вручную.
- Ночная автопубликация устраивает; клиентам давать ссылку на сайт, а не файл.

## 11. Правила для коллег (кратко; полностью — в README.md)

- Структура — стилями «Заголовок 1/2/3» (из них оглавление), не жирным текстом.
- В заголовке раздела про один маркетплейс писать его название (на этом работает фильтр).
- Скриншоты — картинкой «в тексте», подпись следующим абзацем «Рисунок N – …».
- Выноски: абзац начинается с «Важно:», «Совет:», «Осторожно:», «Примечание:».
- Ссылки на другие разделы — через «Вставить ссылку → Заголовки в документе», не копировать URL документа.
- Каждое изменение — строка в «Истории изменений» (если раздел заведут).

## 12. Заметки для Claude (технические)

- Windows, Git Bash + PowerShell; Python 3.13. В выводе кириллица: в скриптах `sys.stdout.reconfigure(encoding="utf-8")`.
- Правки делать через Python-скрипты в scratchpad или Edit; в heredoc через bash `\b`, `\x08` и `'`
  легко ломаются — длинный код лучше писать во временный файл через Write.
- Встроенный браузер Claude: локальные файлы (`file://`) он не исполняет — поднимать `python -m http.server`.
  Когда панель браузера скрыта, IntersectionObserver/ленивые картинки/анимации «засыпают» — проверки
  прокрутки делать через JS (`dispatchEvent(new Event('scroll'))`) или после скриншота.
- Исходный .docx от пользователя (резерв): `C:\Users\Emple\Downloads\Руководство по работе с модулем «Управление Маркетплейсами на 1С».docx`.
- Коммиты — на русском, с подписью `Co-Authored-By`; после правок `git push` (пользователь разрешил пушить в этот репозиторий).
